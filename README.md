# Система виявлення дезінформації

**Тема дипломної роботи:** «Виявлення дезінформації у текстових даних методами генеративного штучного інтелекту».

**Виконавець:** Кривицький Б.П., група ТВ-52мп
**Керівник:** `Голець В.О`
**Заклад:** НТУУ «КПІ імені Ігоря Сікорського», НН ІАТЕ, кафедра інженерії програмного забезпечення в енергетиці

## Короткий опис

Програма перевіряє новинні тексти на наявність дезінформації. Користувач вставляє текст, а система:

1. виділяє з нього твердження, які варто перевірити;
2. шукає докази для кожного твердження в інтернеті через пошуковий сервіс SearXNG;
3. ранжує знайдені фрагменти моделлю-реранкером і перевіряє їхні джерела;
4. оцінює твердження за допомогою локальної великої мовної моделі (LLM), яка працює в Ollama;
5. виносить вердикт для кожного твердження: `CONFIRMED` (підтверджено), `DISINFORMATION` (дезінформація) або `UNCERTAIN` (недостатньо даних). До вердикту додаються оцінка впевненості, пояснення та посилання на джерела.

Підтримувані мови тексту: англійська, українська, російська, китайська.

Програма складається з трьох Docker-контейнерів:

| Сервіс | Призначення | Порт |
|---|---|---|
| `app` | Веб-застосунок (FastAPI): вебсторінка, REST API та конвеєр аналізу | `8000` (змінюється через `APP_PORT`) |
| `ollama` | Сервер локальної LLM (за замовчуванням `qwen3:14b`) | `11434` |
| `searxng` | Метапошукова система для пошуку доказів | `8080` |

## Необхідне програмне забезпечення

| Компонент | Вимоги                                                                                                                         |

| ОС | Linux або Windows 10/11 із WSL 2. Підійде будь-яка ОС, на якій працює Docker.                                                  |
| Docker | Docker Engine 25.0+ або Docker Desktop 4.27+                                                                                    |
| Docker Compose | v2.24+                                                                                                                          |
| GPU (рекомендовано) | Відеокарта NVIDIA з ~13 ГБ відеопам'яті для `qwen3:14b` (~10 ГБ займає LLM, ~2–3 ГБ застосунок). Для менших карт є `qwen3:8b`. |

| Оперативна пам'ять | `16gb`                                                                                                                         |
| Місце на диску | `8-10gb`: тут зберігаються образи, модель LLM та моделі Hugging Face                                                           |
| Мережа | Доступ до інтернету: під час першого запуску завантажуються моделі, а під час роботи виконується пошук доказів                 |

Python, бібліотеки (PyTorch, spaCy, transformers, FastAPI тощо) і мовні моделі spaCy встановлюються всередині Docker-образу автоматично (див. `requirements.txt` і `docker/app/Dockerfile`). Окремої бази даних встановлювати не потрібно: черга перевірок і кеш зберігаються в Docker-томах (`app-var`, `app-cache`).

## Встановлення та запуск

1. Клонуйте репозиторій:

   ```bash
   git clone https://github.com/2026-TV-52mp/Kryvytskyi_BP.git
   cd Kryvytskyi_BP
   ```

2. Створіть файл налаштувань:

   ```bash
   cp docker/.env.example docker/.env
   ```

3. Відкрийте `docker/.env` і вкажіть у `SEARXNG_SECRET` випадковий ключ. Згенерувати його можна так:

   ```bash
   openssl rand -hex 32
   ```

   За потреби змініть інші параметри: модель (`OLLAMA_MODEL`), порт (`APP_PORT`), логін і пароль для доступу (`API_BASIC_AUTH_USERNAME` / `API_BASIC_AUTH_PASSWORD`). Опис кожного параметра наведено в коментарях у файлі.

4. Запустіть стек.

   **З відеокартою NVIDIA:**

   ```bash
   docker compose --env-file docker/.env up -d --build
   ```

   **Без відеокарти (лише CPU).** Модель працюватиме повільно, тому в `docker/.env` краще вказати `OLLAMA_MODEL=qwen3:4b` або меншу:

   ```bash
   docker compose -f docker-compose.yml -f docker-compose.no-gpu.yml --env-file docker/.env up -d --build
   ```

5. Дочекайтеся, поки всі контейнери отримають статус `healthy`. Під час першого запуску завантажується модель LLM, і це може тривати довго.

   ```bash
   docker compose ps
   ```

6. Відкрийте у браузері: <http://localhost:8000/>

Зупинити стек: `docker compose down`. Завантажені моделі та кеш зберігаються в Docker-томах, тому наступний запуск буде швидшим.

## Інструкція користувача

### Робота через вебсторінку

1. Відкрийте <http://localhost:8000/>. Якщо в налаштуваннях увімкнено Basic-автентифікацію, введіть логін і пароль.
2. Вставте текст новини в поле введення. Максимальна довжина за замовчуванням становить 20 000 символів.
3. Натисніть кнопку **Verify**.
4. Дочекайтеся результату. Біля кнопки показується стан перевірки (у черзі / виконується). Перевірка одного твердження може тривати кілька хвилин, бо пошукові запити навмисно виконуються з інтервалом, щоб пошуковики не обмежували доступ.
5. Перегляньте результати. Для кожного знайденого твердження показується картка з такими даними:
   - **вердикт**:
     - `CONFIRMED`: твердження підтверджується джерелами;
     - `DISINFORMATION`: твердження спростовується джерелами;
     - `UNCERTAIN`: доказів недостатньо, щоб зробити висновок;
   - **Score**: оцінка впевненості у відсотках;
   - **пояснення** вердикту;
   - **Sources**: список джерел із посиланнями.

Якщо в тексті немає тверджень, які можна перевірити, з'явиться повідомлення «No check-worthy claims found in this text».

### Робота через REST API

- `POST /api/v1/checks` з тілом `{"text": "..."}` ставить текст у чергу. У відповідь повертається `id` перевірки.
- `GET /api/v1/checks/{id}?wait=30` повертає стан і результати перевірки. Параметр `wait` задає, скільки секунд чекати завершення перевірки (довге опитування).

Приклад:

```bash
curl -X POST http://localhost:8000/api/v1/checks \
     -H "Content-Type: application/json" \
     -d '{"text": "Текст новини для перевірки"}'

curl "http://localhost:8000/api/v1/checks/<id>?wait=30"
```
